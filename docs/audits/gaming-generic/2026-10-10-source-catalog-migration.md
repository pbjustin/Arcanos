# Gaming discovery and extraction data migration

## Scope and inventory

This migration separates existing discovery/ranking and publisher-layout knowledge from the algorithms in `src/services/gamingWebContext.ts` and `src/services/gamingDocumentExtraction.ts`. It preserves the initial behavior; it does not add an acceptance exception, publisher adapter, domain score, seed URL, or extraction selector.

All four pure data modules declare independent schema/policy versions, revision `2026-10-10.1`, repository-default provenance, the migrated baseline SHA, and owner-review policy. They contain no acquisition, environment access, logger, storage, provider, or source-validation call. The separate game identity registry owns aliases and game/edition relationships; this catalog keeps display names as discovery keys and delegates canonicalization to the existing game-detection interface.

## Compatibility and authority boundaries

The discovery catalog remains an optional seed list. The existing `ARCANOS_GAMING_CURATED_SOURCES_JSON` mechanism continues to accept configured sources for games absent from that list. Unknown source domains continue through generic extraction. Neither a catalog entry, a configured game label, a matching keyword, a preferred selector, nor a domain score supplies acquired evidence, proves game identity, or grants publisher authority. Normal protected acquisition, resolver integrity, source policy, CLEAR identity/applicability checks, evidence selection, and generation readiness remain required.

The domain matcher retains exact-host and dot-delimited subdomain matching. Profile order, preferred-selector order, generic fallback selectors, caller option overrides, junk filtering, HTTP/access controls, and all resource caps are preserved. A new profile requires measurable layout evidence and review; it must not bypass a 403, authentication, paywall, robots restriction, or source-use policy. Changes to source-policy authority or durable-storage permission belong to their existing reviewed policy rather than this ranking catalog.

Reviewed cross-origin redirect rules remain stricter than discovery-domain matching: exact host membership for both hops and their existing path predicates only. The two migrated rules preserve `/wow/` prefix matching and `/patchnotes` equality or `/patchnotes/` prefix matching, respectively. No new host, subdomain, path, HTTP downgrade, forbidden port, credential-bearing URL, DNS destination, or authority grant is introduced; each hop still passes normal admission and transport checks before connection.

New game recognition belongs to the versioned identity registry or conservative acquired-title path. New discovery seeds can be configured using the existing environment contract or owner-reviewed catalog data. Catalog or publisher-profile data changes should increment their revision; semantic schema changes should increment their version. No production variable changes are part of this migration.

## Verification

Before the migration, the exact existing behavior suites `tests/gaming-web-context-quality.test.ts` and `tests/gaming-publisher-extraction-regressions.test.ts` passed: 2 suites / 142 tests / zero skips, using Node 24.18.1/npm 11.16.0. After the migration, the same suites again passed: 2 suites / 142 tests / zero skips. They cover built-in routing and topic selection, publisher profiles, unknown-domain generic extraction, unknown-game configured seeds, independent acquired identity, malicious source text, redirects/private targets, provenance, truncation, and cache reuse. No trivial data-copy tests were added.

These are local mocked-acquisition and synthetic extraction checks, not live publisher acquisition or Trinity generation proof. Exact implementation commit and the final combined type/lint/full-CI/preview outcomes are recorded by the task's final verification report.

Before the preference-data migration, `tests/gaming-guide-outcomes.test.ts` and `tests/gaming-clarification-operation-budget.test.ts` passed: 2 suites / 56 tests / zero skips. After migration those suites plus `tests/gaming-clarification-workflow.test.ts` passed: 3 suites / 68 tests / zero skips. They preserve public hint redaction, configured decision resolution, comparison handling, revision/idempotency behavior, terminal outcomes, and operation limits. The new publisher-profile and preference data must join the explicitly reviewed sealed graph with semantic pins; no network wrapper, provider, storage, logger, or environment-access capability is added.

Before and after the transport-data migration, `tests/gaming-document-resolution.test.ts`, `tests/gaming-protected-transport.test.ts`, and `tests/gaming-source-acquisition-preview.test.ts` passed: 3 suites / 164 tests / zero skips each. They execute the production resolver's two permitted pairs and unapproved-host/path rejections, HTTPS, redirect count/loops, DNS pinning, certificate behavior, sensitive URL admission, byte bounds, and pure preview policy behavior. The transport-data module also requires a reviewed sealed-graph node and semantic pin.

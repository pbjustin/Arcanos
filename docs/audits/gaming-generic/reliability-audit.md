## Minimal dependency order and measurable verification

1. Correct source-global versus locally scoped identity before changing extraction or corroboration. Keep security and conflicting-primary declarations as irreversible rejection decisions within one evaluation.
2. Move recognition/edition data into the identity registry while retaining generic structural tuples and platform identity. Validate unknown title evidence from acquired content, never candidate hints or URL names.
3. Add optional claim summaries after selection and full-pool conflict inspection. Test the same tuple repeated on one publisher, distinct known independent families, unknown ownership, syndicated passages, qualifier differences, and conflicting values. An accepted single-source answer must stay explicitly attributed.
4. Expand publisher-shaped synthetic fixtures across unrelated known and unknown titles. Compare generic extraction versus existing profiles with intact record recall, false admission of malformed records, extraction counts, and bounded latency. Add an adapter only where the paired fixture demonstrates a generic failure and a safe improvement.
5. Add cache measurements without infrastructure changes: two identical authorized local acquisitions should perform one fetch within TTL; policy/schema/version changes and expiry should prevent reuse. No transient workflow may invoke ingestion or persist evidence. Existing caches do not prove source revision freshness.

No behavioral tests, live acquisitions, provider calls, PostgreSQL operations, deployments, or production writes were run as part of this read-only baseline audit.

## Implementation and local evidence after the baseline

The optional claim summary is implemented in `src/shared/gaming/gamingClaimCorroboration.ts`. It reuses the production structural grammar through `readGamingStructuralClaimAssertion`, retains request game/edition/patch/platform context, and requires prior backend identity/applicability assessment before a report can earn corroboration credit. Only matching intact supported structural tuples are compared. Arbitrary prose remains unverified. Family mappings are separately versioned in `src/shared/gaming/gamingSourceFamilyData.ts`; they grant neither game identity nor source authority. The initial conservative corporate groups require owner review as part of this private draft change. Their provenance references are registry review inputs, not independent acquired gameplay evidence or evidence that legal pages were fetched in this session.

Verbatim reports connect publication lineages transitively, including through an unknown host; unknown hosts add no independent-family credit. The output has bounded hashed claim identities, statuses and source/evidence IDs, with no passages or claim values. The hybrid workflow computes it from the actual selected backend evidence set and logs versions, hashes, counts and codes. CLEAR adds warning findings for single-source, conflicting or unverified reports. Existing full-pool conflict, freshness, authority and security gates retain decision authority; clearly qualified single-source eligibility is unchanged. This is an optional classification of source reports, not proof of in-game observation.

A confirmed generic request-scope defect surfaced while testing this handoff: `assessGamingStructuralUsability` removed URLs for lexical terms but still scanned the raw request for opaque in-game identifiers. A supplied URL such as `https://publisher.example/record-7` thereby imposed `publisher.example` and `record-7` as unsupported gameplay identities. A focused regression failed before repair. The function now applies the existing retrieval URL boundary before claim-shape, field-binding and identifier checks. The original caller request and required source identities remain intact. Real punctuation in gameplay identifiers remains substantive, and URL-only prompts still cannot establish a claim.

Pinned toolchain used for local evidence: Node `24.18.1`, npm `11.16.0`. At the uncommitted integrated tree, the new claim summary tests and v2 selected-evidence handoff tests pass. The latter retain the real candidate acquisition, protected mocked HTTP, extraction, source CLEAR, selection and freshness path, then deliberately stop before any provider or answer audit. They verify acquired scope and reviewed family grouping, selection of one sufficient source, rejection of frontend publisher hints as independence, and absence of transient ingestion. Their success does not prove Trinity or live acquisition. The root validation report owns final commit SHAs, complete suite status, CI, preview and PostgreSQL evidence.

Existing cache measurement used the production cache paths with sealed fixtures: `tests/gaming-structured-resources.test.ts` and `tests/gaming-web-context-quality.test.ts`, selected with `--testNamePattern=cache`, produced 7 passed tests (190 other tests were not selected). The paired guide requests verify two requests reuse one mocked acquisition; spoiler filtering is reapplied on the cache hit. Structured-resource checks verify an identical payload hits and changed payload/content/metadata or adapter version isolates the entry. This is a measured synthetic acquisition reduction from two fetches to one for that pair, not a live latency, throughput or cost benchmark. Existing 100-entry document-cache bounds and version keys were inspected; no cache service, durable write, retention migration or production operation was introduced.

## Final corroboration lineage correction

Independent candidate review reproduced a weakness in the first optional report: `assessGamingClaimCorroboration` hashed complete serialized unit text, including headings and captions. Identical parser-owned fields could receive separate lineage credit when presentation differed. Two negative regressions failed before correction. Rule `gaming-claim-corroboration/v2` hashes sorted normalized field label/value pairs and local qualifiers; heading, caption, byline and column ordering differences no longer create independent credit. The final focused pure and real-hybrid handoff set passes 28 tests, including copied-record, transitive unknown-family, same-family, scope and conflicting-qualifier controls. Single-source records remain usable under the existing evidence policy.

This is exact canonical-content deduplication and reviewed publication-family agreement. Edited labels/values and paraphrases can evade that deduplication. The report does not prove independent authorship, publisher ownership at acquisition time, or gameplay truth. Owner review of family provenance and broader live validation remain required before production use; the report never supplies generation authority or new provider claims.
